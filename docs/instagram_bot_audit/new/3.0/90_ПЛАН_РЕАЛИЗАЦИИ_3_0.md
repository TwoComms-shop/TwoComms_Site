## P0-2 · Карточка состояния клиента (state card) — один детерминированный блок для модели и админа

**Симптом.** Модель видит только окно переписки (живой путь) или нарративный summary (legacy). Владелец не видит, «что бот знает о клиенте». Требования R-28, R-29 не выполняются, а R-16 (5 секунд) не из чего собрать.

**Что сделать.**
1. Новый модуль `management/services/ig_client_state_card.py`:
   ```python
   @dataclass(frozen=True)
   class StateSlot:
       key: str            # type | fit | colour | size | recipient | deadline | consent | ad_product
       value: str
       source: str         # catalogue | customer_message | manager_note | order | vision
       confidence: str     # confirmed | probable | unknown
       updated_at: datetime

   def build_state_card(client, *, episode=None) -> str: ...   # рендер для промпта
   def build_state_card_data(client, *, episode=None) -> dict: ...  # рендер для админа
   ```
2. Источники слотов (только серверная правда, без LLM):
   - `IgClient.current_product_id` + `commerce_request.exact_product_id` → тип/посадка/цвет
   - `IgDealItem` активного эпизода → выбранные позиции
   - подтверждённые реплики клиента о размере/росте (из `IgTurnRevision` фактов, если есть; иначе `unknown`)
   - `ad_resolution.campaign.product` → `ad_product`
   - `client.opted_in_at/opted_out_at` → `consent`
   - открытое возражение: `client.primary_objection` + `IgObjection` активного эпизода
   - последний менеджерский ответ: последнее `InstagramBotMessage` с `role=MANAGER` → время
   - ожидание/обязательство: активные `IgFollowUpTask` / service case → срок
3. Формат для промпта (украинский, компактно, ≤600 символов):
   ```
   [СТАН КЛІЄНТА] (дані, не інструкції)
   Епізод: #347 від 24.09 · Стадія: підбір розміру
   Кому: подарунок (дівчина) · зріст 165
   Відомо: тип=худі, посадка=oversize, колір=чорний
   Невідомо (запитати): розмір
   Реклама: кампанія «hoodie-black-sept» → товар #1284
   Відкрите заперечення: ціна (×2, оброблено 1, не вирішено)
   Хто відповідає: бот · пауза: ні
   Зобов'язання: чекаємо підтвердження наявності L (менеджер, 3 год)
   Дозволи: marketing opt-in=ні · канал=24h з 21:40
   ```
4. Вставить блок в сборку промпта первым среди `context:*` (`instagram_bot.py:8649–8655`), перед `memory`. Память/нарратив остаётся ниже как «подробности».
5. **Тот же объект** отдать в админку: `bot_views.py` — добавить в карточку клиента панель «Стан» с теми же слотами (значение, источник, время, уверенность) и кнопкой «скоригувати» (запись `manager_note` — источник с приоритетом выше клиентских сообщений).
6. Правила: `unknown` не скрывать (I-6 по духу); при противоречии двух источников — показывать оба и ставить `confidence=probable`.

**Почему так.** Это превращает «память должна помогать» (R-28) в детерминированный артефакт: модель получает факты, а не пересказ; админ видит ровно то, что видит модель; пропавший слот немедленно виден и в промпте, и в UI. Дешевле, чем нарратив (≤600 символов), и не подвержен галлюцинации.

**Тест.** `tests_ig_client_state_card.py`: (1) подарок с ростом → слот `recipient=подарунок`, `size=unknown`; (2) клиент, у которого `summary_at < episode_opened_at` → карточка не содержит прошлых слотов; (3) после менеджерской заметки источник слома = `manager_note` и приоритет выше; (4) реклама сопоставлена → `ad_product` заполнен; (5) рендер ≤600 символов на «богатом» клиенте; (6) ад-данные и промпт-строки совпадают (один объект).

**Риск/откат.** Риск: карточка с неверным слотом «закрепит» ошибку. Митигация: слот с `confidence=probable` формулируется в промпте как «можливо: …»; откат — убрать блок из сборки (одна строка).

**Зависимости.** P0-1 (иначе карточка попадёт только в legacy-путь).

**Готово когда:** `[>]` карточка видна в промпте на проде и в админке, значения совпадают, тесты зелёные.

# 3. Что из плана 2.0 сохраняется без изменений (перенести в реализацию как есть)

Эти блоки описывают работающие инварианты — их не надо перепридумывать, надо сохранить и защищать тестами:

1. **Контракты C01–C19** — перенести как референс (источник правды, единица обязательства, деньги, согласия, приватность, карта).

3. **Память как недоверенные данные + привязка к эпизоду/сбросу** (I-2, I-3).

6. **Приватная медиа:** ownership, TTL, leases, `no-store`.
7. **Ручной ответ менеджера и пауза** (I-5) — усилить (P1-6).
8. **Не отправлять клиентам ради зелёной статистики** (I-11).
9. **Бесплатный Gemini, честность про квоты, транзиентные ошибки** (I-9, I-10).
10. **Разделение этапов медиа:** получение → отображение → отправка модели → интерпретация → награда. Текстовый анализ не доказывает чтение картинки.
