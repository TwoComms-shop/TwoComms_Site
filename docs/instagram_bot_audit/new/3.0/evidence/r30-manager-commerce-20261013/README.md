# Engineering 38 · Уточнение товара и безопасное оформление

Статус: ✅ код436d5343c выпущен и runtime/authenticated UI проверены; [production evidence](PRODUCTION_RELEASE_2026-10-13.md). Полная архитектура расширения — [ARCHITECTURE.md](ARCHITECTURE.md).

## Что проверяется в этом блоке

- Обычный точный каталожный товар с положительным остатком не создаёт лишний запрос менеджеру. Нестандартный цвет/размер и неизвестная комплектация создают точную source-bound заявку/Telegram, а не утверждение о наличии или ссылку на прежнюю вещь.
- Исправление выбора, разные позиции, отрицание/цитаты, язык и восстановление после сбоя сохраняют предмет вопроса. Уточнение не разрешает выдумать состав, люверсы, производство или срок прибытия.
- Физическое AVAILABLE менеджера при нулевом учёте разрешает явный абсолютный пересчёт и существующее оформление. Права первоначального автора решения заново проверяются при новом складском действии; историческое решение не стирается.
- Оплата и договорённость должны явно совпадать в UAH; конфликт валют оставляет подтверждённую оплату для менеджера и не создаёт ложный заказ.
- Основная админка показывает текущего Instagram-клиента и понятные параметры custom OrderItem. Отвязанный/удаляемый клиент не раскрывается; удаление блокирует новый ручной заказ.
- В интерфейсе количество показано один раз; история подписанного offer не переписывается; точный текст клиенту можно раскрыть. Статусы/ТТН/стоимость остаются видимыми, подробные часы перевозчика раскрываются отдельно.

## Ещё не закрыто этим срезом

Утверждённое менеджером noncatalog/mixed коммерческое предложение, фото, source-bound custom checkout; оформление только готовой части и позднее продолжение; согласие на точный список ожидаемых вещей; фактическое разрешение Instagram на будущую доставку сообщений; автоматические несколько ТТН. Эти этапы 39–41 остаются в плане отдельно. Обычное business opt-in не расширяет окно канала.
