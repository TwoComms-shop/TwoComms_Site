# Dated customer memory · 08.10.2026

## Contract

`captured-memory.timeline.v2` keeps at most eight exact, complete customer source
sentences, backend event dates/time basis, immutable IDs/digests and nullable event
scope. Topic hints describe interests, gifts, self-purchase, recipients, questions
and corrections; they grant no current order, selection, stock or payment authority.
Dates mentioned by the customer remain quoted text, not backend event time.
Contact details are rejected rather than rewritten into misleading quotations.

The single existing management generation request receives verified retained events
and a complete new delta (24 messages / 12000 characters; complete generation source
bodies max2000 each). It does not summarize old generated prose or reread the entire
conversation. Nonempty omitted source bodies cannot advance a head. Extractive
selection, source/namespace/reset/erasure/hidden checks, both backend clocks,
owner/deadline/admission and publication CAS all precede head publication.
Bootstrap and retention omissions are explicit; this is bounded recall, not a claim
of complete lifetime history or verified commerce facts.

The historical-as-of reader authenticates the saved head and every source, admits
only event-time and PK values within the sealed request, and provides the complete
fresh delta. A fresh USER enqueue does not hide a usable historical head. Future
heads, source edits, privacy changes and over-budget deltas cause named omission.
The same frozen read feeds the actual live Gemini prompt, client-state narrative and
text-free actual-request metadata; later mutable head changes cannot replace it.
If the context or policy budget drops required delta, dependent memory is omitted.

Background CRM receives dates and the same verified gap; prior-episode observations
remain context but cannot become current operational evidence. Later accepted input
coalesces through the existing job owner. A historical event boundary cannot borrow
today's payment/order truth or publish repeat-purchase authority.

## Activation and limits

Owner-authorized defaults enable timeline generation only through the existing one-job
background tick after customer and CRM work. Active accounting and enforced non-live
admission remain mandatory, with source/privacy/owner and priority rechecks immediately
before physical dispatch. Explicit environment flags retain rollback. Automatic status
and readiness perform zero provider I/O. No global historical backfill or new worker.
Production effective unified context mode is required for live consumption; legacy
rollback deliberately omits v2 through the strict v1 reader.

This block does not close the full P5-1 passport: immutable typed-chain checkpoint,
512-revision recovery, source/key retirement, long-chain CPU/p95 and natural cohort
acceptance remain open. No schema or SQL guard relaxation.
